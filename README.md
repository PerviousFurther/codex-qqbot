# llm-watch-video

A QQ chat and web-content assistant powered by Codex and restricted MCP tools. It supports private conversations, authorized group participation, general website browsing, public-content discovery/reviews, received images/audio/video/GIFs, and persistent conversation files. One global persona, a small role-state snapshot and optional shared Markdown notes provide continuity without merging private histories.

SnowLuma integration uses upstream `@snowluma/sdk@2.2.1`: authenticated OneBot WebSocket events, guarded HTTP sends and SDK streamed file uploads. Official Tencent QQBot interfaces are removed. Startup requires an explicitly configured account, administrator QQ numbers and separate HTTP/WebSocket tokens. Source integration has offline coverage and the deployed application has passed connection/status checks; live QQ command and reply validation remains an operator step. Menus display copyable commands because this channel does not provide the former official bot keyboards.

See [HANDOFF.md](HANDOFF.md) for deployment status, commands and volume locations; [docs/architecture.md](docs/architecture.md) for module contracts; [AGENTS.md](AGENTS.md) for development rules; and [docs/audio-decoder.md](docs/audio-decoder.md) for local speech recognition.

## Command interaction

SnowLuma menus retain named commands. Send `/help` for help or `/settings` from an explicitly bound administrator private chat for management. Group actions use the actual numeric QQ group ID, for example `/group view 123456789`, `/group allow 123456789` and `/group remark 123456789 Weekend discussion`. Discover current groups with `/groups` first.

Files, attachments and record entries use stable object references where a public identifier is unavailable: `/files current view #1`, `/files current export #1`, `/files current delete #1`. The same object keeps its reference across operations, menu refreshes and restarts. References are bound to the current conversation and source list; `#1` from private files cannot address a group file or attachment. Names remain beside each command in menus. Editable commands include parameter names, examples and scope/range hints. Common `/models`, `/thinking`, `/persona`, `/preferences` and navigation commands retain their names. Bare numbers are not menu selections; `/action` is removed.

Deletion confirmation references remain single-use and expire after ten minutes or restart. All commands re-enter the existing backend permission and source checks; references do not grant access, revive removed objects or execute automatically. Website approvals retain their existing host scope and expiration.

## Access and management

In an administrator private chat, `/groups` refreshes group IDs and names through the authenticated SnowLuma SDK. The list and group settings show the group name (or operator remark) and numeric QQ group ID. Only the current account's channel records appear in this list; retained legacy records remain stored. New discoveries require explicit authorization and feature enablement. A refresh failure is shown with cached information. Directory absence is not departure evidence, and refresh cannot restore a recorded departure.

Administrator authorization requires explicit current bindings. The first-message administrator claim, `admin.json` fallback and `WATCH_ADMIN_OPENIDS` configuration reader are removed. Stored files are not deleted by this code cleanup. SnowLuma account IDs must not inherit official OpenID administrator/group grants. The gateway login identity is verified before accepting events. Current identities include the bot account and sender QQ number (`sl~account~qq`); retained legacy groups are excluded from new-channel scheduling and outgoing aliases, without changing their saved settings. QQ group ownership, administration and nicknames do not confer bot privileges. Group authorization, collection and proactive features remain separate settings.

| Commands | Purpose | Access |
| --- | --- | --- |
| `/help`, `/status` | Help and current conversation status | Conversation users |
| `/history [page]`, `/content id` | Public webpage/video/audio facts and short reviews | Conversation users |
| `/settings`, `/manage`, `/groups [page]` | Private/group permissions, task switches and schedules | Administrator private chat |
| `/models [page]`, `/model model-name`, `/thinking` | Conversation model and supported reasoning effort | Administrator private chat |
| `/persona`, `/preferences` | Global persona and administrator content preferences | Administrator private chat |
| `/stop [group-id\|all]`, `/pause` | Stop tasks and invalidate unsent work | Administrator private chat |
| `/memory`, `/group-memory group-id`, `/compact`, `/reset` | Retained records, context refresh/compaction and confirmed clearing | Administrator private chat |
| `/files`, `/media` | Scoped files/shared notes and received/saved media | Administrator private chat |
| `/debug` | One metadata-only diagnostic TXT report | Administrator private chat |

Administrator home groups settings under Private chat, Groups, Persona, Content preferences, Web browsing and Data. Reading pages does not enable features or resume stopped tasks. Slash commands, including malformed/unknown commands, finish locally before inference; read-only pages bypass model queues, model/session changes serialize, and stop acts immediately. Management pages send Markdown followed by separate copyable command lists; ordinary replies have no automatic menus.

`/persona custom <description>` sets a global persona with an offline 5,000-token limit; overflow preserves the previous value. `/persona reset` restores the natural assistant. Persona changes apply next turn on the existing thread without rewriting video facts/reviews or changing permissions. Model/reasoning choices remain conversation-scoped.

Content preferences support `/preferences topics ...`, `/preferences avoid ...`, `/preferences duration any|short|medium|long`, and `/preferences style ...`. Short is up to ten minutes, medium is 10–30 minutes, and long is over 30 minutes. The literal `清空` clears topics/avoid; `/preferences reset` restores defaults. Current explicit requests take precedence.

## Conversations and groups

Private and group turns share `ConversationRequests` for scope-local serialization, received-message capture and administrator feedback, and `VideoController.run` for model execution. Their authorization and input-trigger policies remain distinct. Private ordinary messages use the foreground queue. All non-command group messages, including mentions, use one collected discussion batch. A mention triggers the batch immediately; otherwise any configured count/character/latest-message wait threshold triggers it (defaults: 20 messages, 1,000 characters or 180 seconds after the latest message). Natural participation and idle starters require authorization, collection and their own enabled switches. Collection alone does not make the bot speak. Natural participation may answer, react, ask questions or stay silent. Idle starters make one attempt per quiet period, one hour by default; foreground work takes priority.

Input receipts track exact messages already supplied to the model, independently of replies or completed-batch bookkeeping. Accepted input is never automatically replayed after silence, cancellation or delivery failure. New turns do not attach recent history. Records retain complete credential-redacted text for seven days without a message-count limit; batches supply up to 40 new messages inside the configured window (ten minutes by default). Group threads expire with that window; retained originals and model preferences remain. Explicit current-group recall/summary compaction is available without consuming pending input.

While a turn is active, conversation-local event tools can read new messages, wait for a reply (30 seconds by default, at most 300), or hold a turn-owned interruption guard. Without a guard, unread eligible input has a ten-second intake deadline before cancellation. Other conversations are unaffected. Input receipts survive interruption; successor handoffs contain bounded task IDs and accepted-send facts rather than copied incoming bodies. Media completion notices steer only the current turn. Turn closure awaits media cleanup before session reuse.

Foreground private turns and reply-authorized discussion batches may send to backend-authorized opaque aliases for eligible groups, administrators and known private contacts. Models may choose any offered target without a separate user request or approval. The private-chat access switch gates incoming non-administrator requests, not outgoing messages; recipient stops still apply. Each target requires a separate sequential call. Routing does not read the target's history or expose source chat bodies/identities. Idle starters remain current-group-only; private discovery/ordinary background browsing have no chat sending tool. Content pushes retain ten-minute spacing and permanent source-ID deduplication. Existing delivered IDs remain effective.

At the start of each reply-capable turn, the model is encouraged to retrieve relevant conversation context or public memory notes when continuing a topic, and to use native web search for current or uncertain public facts. The `send_reply` description repeats a short evidence check before sending. These are relevance-based suggestions, not mandatory searches, automatic history injection or a merged model thread. Private chat material must never enter public searches.

Cross-chat context is queried on demand with `list_context_chats` and `read_chat_context`, without automatically combining every conversation into one model thread. Authorized collecting, unpaused groups are readable from authorized foreground private turns and reply-capable discussion batches. Each private chat controls its own sharing with `/context-sharing` (default off); administrators also find it under Private chat settings. Sharing covers retained messages, images, attachments, nested records and recorded bot replies, including pre-opt-in retained material. Existing message/image/audio/media/file tools accept `context_chat` plus `turn_id` to select that evidence. Reads recheck live sharing, source access, stops and retention, including cached media. Turning sharing off prevents later reads but cannot recall evidence already supplied to another model or explicitly saved copies. Project files, other conversation workspaces, backend identities, credentials and login notices remain unavailable.

Confirmed substantive bot submissions are archived from deployment onward, including actual image/audio bytes; old unrecorded replies cannot be reconstructed. Management pages, feedback/errors and login material are excluded. Seven-day retention applies without incoming/outgoing count limits. Reply text is stored completely after credential redaction, without changing sent prose. Local archive failure is reported separately and never retries or reverses a successful send. Queries retain keyword/received-time filters and bounded pagination. Shared reads preserve input receipts and task state; sending aliases and private-input acceptance do not grant history access.

## Tools, media and files

The bot uses native live web search and an explicit MCP tool allowlist. Public page/download/rendering access checks a backend domain/subdomain allowlist, public addresses and redirects. Allowed content is untrusted. `read_webpage` returns bounded text/links. `open_webpage` creates or reuses one turn-owned public browser page; URL changes replace its context while reusing the browser process. `scroll_webpage` scrolls without reloading, `screenshot_webpage` captures the current viewport or a viewport-relative crop, and `close_webpage` releases the page/process early. Turn closure aborts work and awaits browser cleanup. Screenshots are actual pixels; accompanying text is a bounded document prefix, not viewport/crop text. `click_webpage`, `type_webpage`, `press_webpage` and `back_webpage` operate the same page and return observed screenshots. Browser snapshots also list up to 40 DOM elements with temporary IDs, text, selected attributes, visibility and bounds. `get_webpage_dom` supports CSS queries/pagination and bounded sanitized HTML excerpts; `click_webpage` accepts an element ID or coordinates. `edit_webpage_dom` removes/hides a selected popup or overlay, optionally releases scroll locks, and returns an updated snapshot. It changes only the temporary page, without arbitrary script/HTML injection. Each listing replaces element IDs; navigation/detachment invalidates them. Navigation, frames and bounded form/API requests retain domain/address/redirect checks; interactions can submit external changes and are never automatically retried. Cookies (including session cookies) are saved separately per conversation and restored across URL changes, turns and service restarts; closing the browser still releases its memory. Cookie files are private service credentials, never model-visible or shared between chats. Local/session storage is not persisted, and some redirect-cookie flows may be incomplete. Browser screenshots stay source-scoped because pages can contain logged-in content. Website login uses only this conversation's cookie jar; compatibility with every login/verification flow is not guaranteed.

`list_webpage_media` discovers HTML video/audio players, including checked child frames, and returns temporary IDs, seekable ranges and text tracks. `read_webpage_media` inspects one actual video-element frame at the current or requested accessible time; it may briefly play muted media to seek and then pauses it. Audio metadata does not mean the bot heard the audio. `get_webpage_subtitles` reads browser-exposed text-track windows; visible custom overlays use screenshots/DOM. DRM, unsupported codecs, canvas-only players and blocked resources remain explicit limitations. Player references expire on navigation, rediscovery or page closure. Media requests use the checked downloader, including Range request/response headers; each media resource allows 16 MiB, other non-image resources 4 MiB. This is browser playback, not universal stream extraction.

`upload_file(turn_id,element_id,file_name)` selects a current-workspace file for a file input or a button opening a file chooser. Save received attachments first. It passes guarded bytes to Chromium, never a host path, and confirms selection only: sites may upload immediately or require another submit click. File-bearing requests allow the existing per-file bound plus 1 MiB form overhead; ordinary requests keep 64 KiB. Full-file multipart/raw requests are supported; larger chunked requests without the complete selected bytes remain unsupported. Access/existence are rechecked before transmission, including delayed submissions/redirects. Inspect the page result and never automatically repeat uncertain uploads.

`remember_content` saves public webpage/video/audio facts, observations and short reviews keyed by public source URL; `recall_content`, `/history` and `/content id` read them. Private/logged-in page contents never belong in public history. Native search replaces site-specific candidate discovery. Existing video facts remain readable and retain stable delivered IDs; dedicated Bilibili APIs, QR login and tools are removed. Old authentication files are preserved unused, without importing their cookies. `/contents` manages the existing content-retention schedule; saved preferences, switches and stops are preserved.

Unknown webpage domains can trigger private administrator approval from an active foreground or reply-authorized group batch (up to three distinct hosts per turn). Administrators use Browsing → webpage permissions, or `/web-access`, to approve/reject pending requests and revoke extra grants. Requests expire after ten minutes, deduplicate by host, and rejection suppresses repeats for an hour. Approval grants that exact hostname globally to already-authorized conversations, survives restart/scoped cleanup, and leaves adult/public-address checks intact. No chat bodies or full URLs enter approval records/notices. Webpage reads and browser requests to unknown hosts can wait for private administrator approval before sending the blocked request. Approval waits share an extra 60-second budget per operation; approval rechecks live source/domain access and continues the same request without replaying clicks, form submissions or prior redirect hops. Denial, expiry, cancellation or timeout ends the wait. Approval does not restart failed operations or stopped tasks. `read_webpage` also requires `turn_id`; native search and selected-file downloads do not initiate approval requests.

Received message bodies use records/components for text, mentions, images, audio, video, files and cards. Unread quote/forward children use body-free record_ref components with messageId and get_message_detail; a reference is not an expanded body. SnowLuma references without inline bodies remain opaque. Explicitly reading a `forward:` reference with the current `turn_id` can acquire that one body through the pinned SDK `get_forward_msg`, then store its returned nodes and media pointers. Capture and parent-page reads never fetch referenced bodies; deeper forwards still need separate reads. Acquisition requires a retained private key from the original event, live source/target authorization and group collection. Old references whose keys were discarded require a resend. Acquired nodes inherit the source record’s retention deadline and do not become new discussion input. Missing quote bodies and absent platform fields remain unknown. Video URLs absent from the delivered card cannot be manufactured. Private and group inputs use the same record projection without a duplicate raw text copy. Text longer than 1,200 UTF-16 code units is folded into a length/message-ID reference; large record projections use `record_ref` with `DETAIL_REQUIRED`. Complete originals remain readable through `get_message_detail` content pages (`content_offset`/`content_limit`, with `contentPage.nextOffset`). Capture has no attachment/mention count or nested depth/node/text limits; repeated/cyclic object references are detected. Previously truncated stored records remain readable, but lost content cannot be restored. `get_message_detail` also returns one direct-child page and up to three actual images by default; deeper nodes need explicit reads. `get_image_detail` reads additional scoped images. `get_audio_detail` requires `qq` (already-delivered ASR) or `local` (configured local recognition), without automatic fallback. Transcripts and inner identities are unverified.

Root and nested quote references use the same parsing rules. Delivered quote snapshots appear once rather than as both quotes and forwards; parallel and forwarded records retain their distinct relations. Complete QQ textual picture descriptors (stated picture type, filename, dimensions, displayed size and an actual allowed QQ media URL) enter the same scoped attachment index before their private URL is hidden. This does not reconstruct missing inner messages, identities or times; bare URLs and unsupported descriptors do not create images. Whole record graphs publish in one transaction, and group collection accepts only the completed captured record. Existing stored records remain readable without a bulk rewrite; missing historical fields and previously discarded URLs cannot be reconstructed.

`read_media`/`close_media` asynchronously sample received or saved video/GIFs within the current turn. The optional received/saved-video `track=audio` branch recognizes explicit ranges up to 120 seconds on the same timeline; frame reads do not start speech recognition. Attachment speech recognition shares one cross-process ASR slot and closes native processes after use. Public direct media uses `save_file(url,name)` first, then `read_media(file_name,...)` for video/GIF or `get_audio_detail(file_name,method=local)` for audio (8 MiB/120s). Authenticated browser streams are not extracted for ASR. See the architecture and audio guide for decoder/cache/lifecycle budgets; sampled frames and speech do not imply full media understanding.

Unified `list_files`/`read_file`/`save_file`/`delete_file` cover conversation workspace files, shared Markdown notes (`area=memory`), retained images (`area=assets`) and conditionally read-only project text (`area=project`). Project access requires an explicit current request by a verified administrator in foreground private chat. Files are data, never executed/imported or used as a process cwd; tools provide no shell, package installation, code evaluation or arbitrary host paths.

Workspace files use flat names, checked byte formats and explicit overwrite. Failed/cancelled writes preserve previous contents. Sources are generated text, obtained allowlisted URLs, current attachments/images, or browser assets. Limits per file: text 64 KiB, image/GIF 16 MiB, audio 8 MiB, video/binary 64 MiB; downloads 64 MiB. There is no file-count quota. Selected files survive context refresh without automatic expiry; scoped clearing removes them. Browser screenshots/player frames require `turn_id` and are temporary until turn cleanup; explicitly `save_file` to retain them. Older saved images remain available with seven-day retention and no count/aggregate-byte eviction.

Media saving defaults to `format=auto`: bounded MP4 encoding, with QQ MP4 passthrough unless bitrate is explicit. `original` preserves bytes, `video` emits MP4, `audio` emits MP3, and `gif` converts the entire source only up to 15 seconds without cropping. Encoding has bounded source dimensions/duration and a 90-second deadline. It does not support multi-gigabyte ingestion or arbitrary document parsing.

Shared notes accept generated public Markdown only. All authorized conversations may read them: private chats, identities, transcripts, credentials and internal instructions must stay out. The shipped `AGENTS.md` guide is read-only; notes are optional untrusted knowledge, not authorization. Scoped cleanup preserves shared notes. The small shared role state holds only mood/public-topic focus, never chat summaries or private interests.

## Replies and operator data

All chat output uses token-bound `send_reply` calls with increasing `part_id`; identical repeats return the original result without replaying delivered messages. Ordinary text stays one verbatim message per call. Local references (`asset://ID`, `attachment://ID`, `attachment://audio/ID`, `/assets/ID`, `/attachments/ID`) split Markdown into ordered text/media/text; explicit media follows text separately. Code is literal, remote Markdown links remain unchanged, and explicit URL downloads retain the allowlist. Saved image/audio can use `media.file_name`. There is no prose splitting, local cooldown, fixed ending or final-text fallback. Final JSON contains only `pauseBrowsing` and nullable `sharedState`; silence does not trigger compensating video shares.

Source/target access, cancellation and asset existence are rechecked before submission and after uploads. Private media/player screenshots stay source-scoped. The common response layer imposes no official-bot passive quotas. Unknown/ordinary delivery failure stops later sends without retry; affected groups use the common stop path. Explicit HTTP 429 or a channel-normalized rejection returns `QQ_RATE_LIMITED`, releases owned reservations and separately notifies administrators without pausing the group or invalidating the turn. Never retry the rejected part. A verified image-size rejection before any submission may permit a later text explanation.

Private administrator Data pages list retained incoming messages, scoped files/shared notes, received attachment indexes and saved images. They support bounded text paging/TXT export, explicit private media opening and confirmed deletion. Private scope is the requesting administrator only; group records require authorization and collection. These are locally retained incoming records, not full QQ history or a complete bot-reply transcript. Removing an attachment pointer preserves message text and independently saved copies. Refresh retains originals/files; clearing needs a ten-minute single-use confirmation and preserves credentials, settings, model/effort, persona, shared state and video facts. Local deletion cannot recall QQ messages or erase provider archives/backups.

One opt-in Run feedback switch (`toolMonitor`) per private/group source controls processing/tool status and elapsed time, sent privately to administrators. Web search/open/find and webpage read/render feedback may show up to three actual event URLs, independent of the webpage allowlist, with adult destinations and credentials rejected and query strings/fragments removed. Search events without displayable URLs say so; no visited URL is invented. Other arguments, result bodies and reasoning remain excluded, and hints never replace substantive replies. URLs are ephemeral feedback only, never diagnostic metadata. `/debug` is the sole technical diagnostic export, assembled from cached metadata without model/platform calls or chat-body reads. Technical failures notify administrators independently of optional feedback; failed notifications do not retry or fall back to the source chat.

Use `/persona custom <description>` in verified administrator private chat to change the global character without editing code. Up to 5,000 tokens are accepted using the pinned local tokenizer; ordinary chat input has no local character rejection limit. Overflow keeps the previous persona. The full saved description is injected, while the settings page shows only a 600-character preview. It applies to private/group conversations on their next turn; an active turn keeps its current instructions. `/persona reset` restores the default. Persona does not change backend permissions or tool policy.

## Public domain database

The bot's web allowlist combines the curated base with forum and social-media categories from the pinned [v2fly/domain-list-community](https://github.com/v2fly/domain-list-community) submodule. Global, Chinese, Iranian and Russian category files are included where upstream provides them. The `category-porn` list and small local overrides exclude known adult platforms (including OnlyFans/Fansly). Adult rules take precedence over grants. Model instructions prohibit accessing adult websites or pornographic pages, including on otherwise allowed platforms; a domain list cannot classify every page on a mixed-content site.

`lib/web-access-policy.mjs` uses the committed compiled snapshot under `lib/web-domains/` for project webpage acquisition. Codex native search stays in live mode without this project domain filter. Offline compilation expands includes, attribute filters and affiliations. Only suffix-domain rules become grants: top-level, exact-only, keyword and regex grants are omitted rather than broadened. Parent grants containing known blocked literal hosts are removed to avoid granting those descendants. Adult deny rules retain suffix, exact, keyword and regex matching. Advertising-tagged grants are omitted. Existing public-address, redirect, resource-size and scoped-media checks remain.

The upstream checkout is reference data rather than a trust certification. Runtime reads only the compiled snapshot and bundled MIT notice, with no network updater or raw vendor checkout in the image. `lib/web-domains/base.json` holds curated domains; `scripts/lib/v2fly-domains.mjs` selects categories and local adult overrides. Updating the submodule alone does not affect access: compile and review the snapshot before deployment. Commands are in HANDOFF.

## QQ process memory recovery

Docker uses `unless-stopped` for crash/host-reboot recovery. The optional host watcher samples gateway memory every 30 seconds and requests a drain after at least five minutes at 85% of its limit. Existing admitted work finishes; new background starts pause. Incoming QQ messages cancel an unsealed drain so conversation traffic takes priority. An idle seal closes the event connection before restarting only the gateway. No task is forcibly cancelled to meet the memory target: after ten minutes the attempt is deferred, with a one-hour attempt cooldown. A two-minute renewable maintenance lease restores admission if the watcher disappears. The short disconnected interval cannot guarantee QQ message delivery or automatic login recovery. Deployment and watcher activation are explicit operator steps in HANDOFF.

Deployment uses one root `compose.yaml` for the application and SnowLuma gateway. Existing QQ volumes and the private network retain explicit external names. See [HANDOFF.md](HANDOFF.md#one-time-transition-to-unified-compose) for the required one-time container transition and routine deployment commands.

`send_reply.interaction` supports poking the authenticated sender of a retained top-level incoming message and adding/removing a QQ message emoji reaction. It uses the current conversation only, with an actual `slmsg~` message reference (pokes also accept a retained `slnotice~` interaction reference); arbitrary QQ numbers, forwarded speakers and cross-chat targets are not accepted. Interactions are sent alone, sharing the normal turn token, ordered part IDs, duplicate protection, group reservations, access rechecks and failure rules. There is no separate feature switch. Accepted interactions do not create fictional text-history records. QQ decides whether the selected emoji/account/message supports a reaction.

The pinned SnowLuma SDK also exposes `get_msg`, `get_group_msg_history` and `get_friend_msg_history`, plus explicit `get_forward_msg`. The application currently uses locally retained event/reply records and explicit forward acquisition; it does not query remote chat history or backfill missed events automatically. SDK availability does not establish completeness, account-side retention or live query success. Local storage continues to own seven-day retention, authorization, supplied-input receipts and batch progress.

## QQ history search

`search_qq_history` explicitly searches SDK-returned history in the current conversation or an authorized turn-local shared alias. The backend pages toward older messages and performs case-insensitive literal keyword matching on top-level text. Models may specify ISO `since`/`until` timestamps with timezone within the last seven days (default: last 24 hours). SDK history has no native keyword or time-seek parameter; reaching an older interval can require multiple calls.

Each call scans up to three 20-row pages and returns up to 60 matching 200-character excerpts, observed time coverage, skipped rows, stop status and an opaque continuation cursor. Continue using the same target and turn; cursors expire after ten minutes and each search stops after 100 pages. Empty, malformed or repeated SDK pages are distinguished; even gateway exhaustion does not prove complete QQ history. Search does not archive remote rows, consume input receipts, expand nested records, download media or expose sender bindings. Results have no local detail references. Group collection/authorization and private sharing/stop/maintenance checks remain live throughout acquisition. Existing retained-record queries remain available for structured details and media.

QQ reaction selection uses `search_qq_faces`: look up a system face by name/keyword or resolve a numeric ID, then pass the chosen `emoji_id` to `send_reply`. The catalog supplies names and aliases without downloading face images; catalog presence does not guarantee reaction support. Accepted interaction results include the actual action, selected message reference, emoji ID and add/remove flag.

Incoming private/group pokes and group reaction additions/removals enter the existing message capture, authorization, batching and turn-intake path. They are labelled interaction records rather than spoken text; reaction targets remain body-free references for explicit detail reads. Pokes aimed at the bot use the existing mention trigger, still requiring group collection, participation and unstopped access. Self-originated interactions are ignored. There is no new switch, automatic history fetch or guaranteed reply. Private notices do not register/unblock outgoing contacts. Service/delivery errors are sent privately to bot administrators; model guidance also prohibits operational-failure notices or interaction-failure apologies to ordinary users and groups.
